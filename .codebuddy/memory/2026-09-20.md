### 关键结论（已对照 VContainer 1.19.0 源码，非仅凭文档）

- `LifetimeScope.Configure` 在 1.19.0 是 `protected virtual`（文档写的是 abstract）。
- `Lifetime` 枚举顺序：`Transient=0, Singleton, Scoped`。
- 注入顺序：构造 → 字段 → 属性 → 方法（`ReflectionInjector.Inject`）。
- 构造函数选择规则：唯一 `[Inject]` > 参数最多；>1 个 `[Inject]` 抛异常。
- 重复注册的真实行为：
  - 具体类型 + `Singleton` 重复 → 构建期抛 `VContainerException: Conflict implementation type`
    （`CollectionInstanceProvider.Add` 只拦这一种）
  - 其它 Lifetime 重复 → 不报错，直接 Resolve 取"最后一个"，全部可通过
    `IEnumerable<T>` / `IReadOnlyList<T>` 拿到
- 集合注入：`Registry.AddToBuildBuffer` 维护 `(service, AnyKey)`，≥2 次注册时把
  `IEnumerable<T>` / `IReadOnlyList<T>` 一起注册；子作用域解析时会通过
  `CollectionInstanceProvider.CollectFromParentScopes` 合并父作用域的注册。
- `IAsyncStartable.StartAsync` 返回类型：UniTask 装上→`UniTask`；Unity 2023.1+→`Awaitable`；
  否则→`System.Threading.Tasks.Task`（本项目 2022.3 走 Task 分支）。
- 诊断 API 的类名是 `VContainer.Diagnostics.DiagnositcsContext`（官方源码拼写如此）。
- 创建子作用域会触发子作用域的 `EntryPointDispatcher.Dispatch()`，集合会合并父作用域注册，
  因此父子作用域不要注册同一批标记接口。

### 代码质量验证方法（很有用，以后可复用）

本机有 .NET SDK（9.0.302 / 10.0.103），可以绕过 Unity 对 `.cs` 做**语法级编译验证**：

1. 在 `Temp/syntaxcheck/` 建一个 csproj：
   `<TargetFramework>net10.0`、`EnableDefaultCompileItems=false`、`ImplicitUsings=disable`、
   `Nullable=disable`、`LangVersion=9.0`，`<Compile Include="..\..\Assets\VContainerTutorials\**\*.cs" />`
2. `dotnet build`，然后过滤错误码：
   - **CS1xxx = 语法错误**（本次 0 个 → 语法全对）
   - CS0246 = 找不到类型（缺 UnityEngine/VContainer，属预期）
3. 关键技巧：把 CS0246 里的类型名去重列出来，**如果没有出现教程自身的类型名，
   就说明所有自研类型引用都解析成功了**（可排除拼写错误）。
4. 结束后删掉 `Temp/syntaxcheck`。

**注意**：PowerShell 里处理中文错误消息，需要用 `[char]0x201C` / `[char]0x201D`
（中文左右双引号）做分隔，不要用正则里的 `"`，否则会被 PS 解析器截断。

### 追加：用户反馈的编译错误与修复

用户报告（唯一一个错误）：

```
Assets\VContainerTutorials\11_CommercialCase\Composition\Lesson11LifetimeScope.cs(18,9):
error CS0246: The type or namespace name 'LifetimeScope' could not be found
```

**原因**：该文件用了 `LifetimeScope battleScope;`，但只写了 `using VContainer;`，
漏了 `using VContainer.Unity;`（`LifetimeScope` 在 `VContainer.Unity` 命名空间下）。
已修复。

**用到的排查手段（值得记住）**：

1. `Library/ScriptAssemblies/*.dll` 的文件列表 = "哪些程序集编译成功了"。
   本例中 `Lesson11.{Domain,Application,Infrastructure,Presentation}.dll` 都在，
   **只有 `Composition.dll` 和 `Assembly-CSharp.dll` 缺失** →
   立刻定位到问题范围在 Composition；`Assembly-CSharp` 是因为依赖 Composition 失败被级联跳过。
2. `Library/PackageCache/jp.hadashikick.vcontainer@5401e5a7eb` 证明 VContainer
   1.19.0（commit 5401e5a7）已成功安装，包本身没问题。
3. `%LOCALAPPDATA%\Unity\Editor\Editor.log`（本次 273MB）里有**全部**编译错误：
   `Select-String -Path $log -Pattern "error CS" -Encoding UTF8` 过滤即可。
   本例去重后只有 1 个错误、0 个警告 → 确认修复后即可全通过。

**重要教训**：
前一步的 dotnet 语法验证**无法发现"缺 using"** —— 因为缺少 VContainer 程序集时，
所有 VContainer 类型都会报 CS0246，真正的漏 using 被淹没在假错误里。
所以必须额外做"类型名 ↔ using"的交叉检查脚本（本次已补做，全部 CLEAN）。
